# Conservative settings/panel A/B migration, runnable offline candidate

Operates on inert 1 MiB image files only. No firmware package, flash driver, device connector, USB, or release functionality. Does not touch panel sector contents, install assets there, or change flash ownership. Not a firmware fit receipt.

- Original settings: 0x9D000 and 0x9E000. Original panel: 0xA5000 and 0xA6000. Owner at 0xAF000 must be exact SMK37DATAX0X plus padding. Decode uses actual production X0X0 magic, object IDs 0/4, 256-byte body offset, header/body CRC and generations. Unknown/damaged headers, oversized payloads, foreign owner and conflicting ties refuse without mutating input.
- New journal carries both exact current/previous payloads and four original per-object sequences, body CRC and legacy-source SHA lineage. Max body 224 bytes, one flash page. A 32-byte new commit header is written last.
- First migration uses two *verified erased* pages at +512 of the active legacy SETTINGS sector for a temporary checkpoint, outside the legacy header and payload. Thus all old generations remain untouched until they are durably checkpointed. Keep temporary checkpoint while writing/verifying regular journal in other sector. Only then erase/write/verify the second regular journal. All other sectors stay byte-identical. Mixed reset reader prefers regular, then temporary, then original records. Offline resume recognizes a precise operation prefix and rejects other modifications. It does not model arbitrary electrical bit subsets.
- The may_retire gate requires both regular journals, same values, consecutive migrated epochs and correct backup lineage. NT: this is a necessary content/lineage check, not permission to write new-region assets. Real retirement additionally requires acknowledgment by the new firmware, reset proof, immutable-region guards and preventing unsupported old installers from erasing reused space.
- Supported rollback restores exact original settings/panel A/B and owner sectors before old app selection, with matching lineage. If a later settings/panel change exists, exact legacy rollback refuses rather than lose it. Post-edit latest-value legacy export and legacy installer integration remain unimplemented. Do not factory-flash output.
- File backup uses exclusive temp-file/fsync/readback/atomic link then parent-directory fsync. It refuses overwrite; source SHA must match before migration. Filesystem backup proof is not proof of atomic device installation.

Run PYTHONDONTWRITEBYTECODE=1 python -m unittest -v in this directory. The migration.py CLI provides backup, migrate, resume and rollback. Each verb accepts a local source image and new output file, and requires --board elite or pro; migrate/resume/rollback also require --verified-backup.

Tests: 35,824 reset prefixes across both boards and either active legacy A/B side; 8,702 edit prefixes; recovery at each named migration phase; unknown state rejection; history/identity and byte-for-byte legacy restoration; erased objects, wrong board, damaged or stale backup, nonempty tail and atomic output no-clobber. No native link, hardware, publication or region reuse.
