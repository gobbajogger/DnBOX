## Reproduction

1. Set ROOT to the fixture workspace and OUT to a private writable scratch directory with an fw subdirectory. Archive the exact SHA above from a source archive or checkout that has the commit, e.g. git -C /tmp/dnbox-arch-exact archive <SHA> | tar -x -C "$OUT/fw".
2. Copy the extracted firmware/src/dsp/s1c/s1c.c to "$OUT/control.c". In "$OUT/fw" apply prefix-glide-lab.patch with patch -p1. Run ROOT="$ROOT" OUT="$OUT" sh "$ROOT/s1-glide-independent/check-six.sh". All six warm unity-gain pairs are rendered with the production s1_part API and are compared byte for byte with the control before the established spectral, level, body, tail and null report.
3. Optional exact-state regression already run: TMPDIR=<writable scratch> sh "$ROOT/perf-final-proof/arch-glide/test-fold.sh" /tmp/dnbox-arch-exact "$OUT/fw" "$ROOT/s1-fix-data/s1.pack". Actual dual renderer objects compare PCM, voice state, all controls, widen buffer and effects arenas, with zero spans, signed zero and changed delay settings.
4. Build with MODEL=elite or MODEL=pro, JIELI_TOOLCHAIN="$ROOT/prereqs/toolchain", AC79_SDK="$ROOT/prereqs/sdk", and ./build.sh in the isolated tree. Save the respective log as <model>.prefix.build.log in this directory. Then run ROOT="$ROOT" OUT="$OUT" sh "$ROOT/s1-glide-independent/check-native.sh" elite and likewise pro, each in fresh emulator output directories. It checks the pinned emulator digest, uses the original 922-event scene and six offsets at 360 MHz strict, and runs the project-seeded S1 factory 63 + Miami + arp scene only after verifying byte-exact project adoption. The cold and warm 2-second controls complete before the first scripted input. Emulator scratch flash is disposable. See the per-shot JSON for observed counts and package hashes.

The sparse index-list variant preserved the six host waveforms but overflowed XIP by 44 bytes Elite and 32 Pro. Compared with the same fresh unedited control, it grew 60 bytes on both. The prefix variant uses no index-list scratch. It saves 32 bytes vs the local baseline on both boards (48/60 bytes free; 512-byte pool margin retained), and remains below the source gate's 1,024-byte XIP headroom. A source patch is retained for investigation only.

The moving-reverb-tap diagnostic uses the pre-existing cubic interpolator and phase fields and leaves delay/reverb allocations unchanged. To reproduce, start from a pristine copy, apply modulation-rejected-lab.patch with patch -p1, compile the candidate arm with the compiler command from check-six.sh (no control PCM equality expected), and score with the same scorer. Theater Organ tail moved from -4.70 to -2.12 dB and spectrum from 9.00/8.22 to 5.43/5.31 dB. Sahara tail moved from +0.57 to -3.42 dB. Only 1/6 of the fixed comparisons passed. That patch is rejected.

Pad delay remains blocked. Existing published-in-thread direct-ring bounds and new sparse-transform evidence leave no credible persistent-memory budget for a general replacement. The candidate glide changes do not modify the Pad or Organ signal path.

If emulator processes are interrupted, keep the per-board receipt JSON copied by check-native.sh. Run `PYTHONDONTWRITEBYTECODE=1 python3 resume-native.py "$ROOT" "$OUT" elite stock` (or `miami`, and likewise `pro`) serially. The resume script verifies the package, ELF, pinned emulator and relevant fixture seed and performs only the missing offsets. Initial concurrent runs encountered host SIGKILL; completed measurements were retained and interrupted cases were retried in series.

## Two-anchor four-bit residual history (rejected)

Each 16-sample block uses 12 bytes: two existing-input binary16 endpoints (4 B), a power-of-two residual scale (1 B), and fourteen signed four-bit residuals (7 B). The linear prediction is between the endpoints. Both endpoints and any residual are directly accessible at a fractional tap. No predictor replay is needed. The ring stores actual delayed input and feedback, with no synthetic excitation. A block uses the existing 32-byte staging array in each active line (96 B stereo, 64 B mono), and adds no persistent memory or staging arrays. 12 B/16 slots is 6 bits per history sample including headers. Each full block packing pass scans 14 residuals for the scale and quantizes 14 more, amortized over its 16 writes. A tap reads at most two reconstructed samples, each constant work. See delay-anchor4-host-cost.log for host code/stack costs, which are not native XIP or timing evidence.

## Structural scheduling feasibility and native slot handback

The transport-gated candidate is retired. Its stock-prefix PCM and admitted kick/snare events passed, and Elite Miami +0 still missed by 3,832 µs with 129 XRUNs.

Compiled the production `plan_cost` directly from the verified source tree and checked every legal split, including the zero-work kit proxy. The retired build's terminal RAM gave plan 0x0b with job estimates [64804, 11987, 83967, 13688, 3861] ticks per 256 frames. That plan was already optimal in the in-order model. Over two 256-frame spans at those same estimates, a scheduler with perfectly busy cores, no waits and unchanged DSP work would save at most 130.4 µs. The prefix vector before the reassignment projected 2,903.7 µs for the best in-order reassignment and 4,359.2 µs for the ideal no-wait limit. The latter is a deliberately optimistic model for the earlier endpoint. All three projections use terminal smoothed estimates. None measures the 14,741 µs callback or bounds savings on every callback.

The source constrains an ownership change in two places. `engine_render` admits physical commands before the first span and advances sequencer events between spans, so speculative work cannot cross either boundary. `run_job` shares the dry/send accumulators and commits 909, 808, A, B and break in that order. A separate render/mix plan would also have to respect the 808 metal workspace borrow and the core-1 failover path. The weighted-PC profile shows the largest work in 909 and Synth One rendering, but does not isolate a proven redundant loop or quantify recoverable stalls at the failed callback. The available observer lacks the required counters on these production images. The duration of the late half's phases remains unverified.

Local focused checks passed 98,368 render shortcut comparisons, the original sequencer regression and the whole-engine arp hook suite. The latter checked exact transport-grid frames, a live tempo change and project reload. The two original native output witnesses remain in `transport-slot-events.json`. No new firmware candidate passed the host credibility check. No new firmware patch or native shot was made. The reserved native slot is available to the release coordinator.
