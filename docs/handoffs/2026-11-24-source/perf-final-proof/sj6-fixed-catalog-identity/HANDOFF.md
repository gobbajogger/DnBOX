An immutable fixed identity is not a removable/side-loaded bank. Fixed v1 keys are exact (bank UUID, program UUID). Order is authored MIDI bank number 0,2…12 followed by authored program position, not archive order or C-reader UUID sort. ## Detached representations

- SOUND: legacy built-ins 0…3 unchanged. Fixed ordinal n 0…639 maps to 4+n in existing 16-bit Sound tag. Base cell[30] carries low byte, old-invalid MSBs of Juno PWM amount bytes [18]/[19] carry high two; old q127 low fields unchanged. Prior parser rejects even low-byte collision 0. New product loader must verify exact base/tag agreement and independently authenticate the resolver's manifest and exact program bytes. Synthetic bool is a fixture seam only. Current runtime and original_sound_value still treat cell[30] as legacy ordinal/index to four static snapshots; changing admissible counts without rewriting resolver, low-byte consumers, note locks and both save/boot paths would be unsafe. Do not expose this through existing eight-bit UI descriptor.
- PAT: each of two existing rsv[voice] bytes reserves one of 64 strictly old-invalid values (82…128, then 159…175) to represent its low six ordinal bits. Its owner nibble in rsv[2] carries upper four. Both independent 0…639 ranges can coexist; any untouched voice keeps exact old code and has zero extension nibble if the pattern owns the extension. Pattern with neither marker retains formerly ignored rsv[2] verbatim, including unknown nonzero values; new claims refuse unknown nonzero rsv[2]. Invalid ordinals, foreign nibble or absent provider fail. No growth or old alias normalized. Actual bound proves all 640 per owner and representative full-range pairs.
- These bit allocations are proposals requiring ownership coordination with other held SuperJ6 lanes. Current BASS note lock already copies base/tag but does not validate/hydrate fixed identities. Future patch needs explicit support, not inference from byte room.
