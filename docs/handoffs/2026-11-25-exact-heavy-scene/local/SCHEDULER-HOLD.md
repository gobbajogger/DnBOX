# Future owner separation, not a patch
Current engine.c c1_allowed excludes Synth One and Chicago, so both render in sequence on C0; 909/808/BREAK may be remote, and Miami is eligible. run_job already has distinct original_runtime_workspace and two output lanes per bass. Each bass owns part/insert state; bass bfx_part_stut_base=-1 avoids other parts' rings. stage_wait orders sum and meter writes, not side effects during render.
* original_runtime_render advances gates, scheduler, voices, reverb/delay and publishes runtime_note -> engine_remote_bass_voice -> remote_dnr3_voice. rd.voice is aligned but not an atomic read-modify-write; when WATCH is armed, overlaps could change pulse order/count even if sample math matched. Capture an owner/job-local event delta with proven bounded capacity, then merge/publish in the existing 909 -> 808 -> bass A -> bass B -> BREAK commit order and apply session-generation checks. Prove ordering/latest pulse with active WATCH, not just PCM.
* fm1_cpu1_wait sets gave_up=1 for bad mailbox (no work), gave_up=2 after 24ms timeout (may have already mutated voices/FX/arp). c1_take_over can run the same job again after wait. Never reissue a started mutable job without exact rollback; 412 usable byte POOL is already below 512, so a duplicate full owner or FX rings is not legal. Investigate independently resumable single-writer stage decomposition or a pure partial job safely reissued. A late/failed job remains a failed deadline.
* Before enabling remote owners, require unstarted vs active interruption proof, ordered Remote effects under WATCH, mix/admission/tick invariants, Core1 ownership, BLE-preemption stack watermark, XIP/POOL, and exact paired phase sweeps with real owner on the intended core.
