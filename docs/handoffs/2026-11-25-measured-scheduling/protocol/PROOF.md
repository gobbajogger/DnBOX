# Core1 ordered join model — NOT connected to audio
Run: cc -std=gnu11 -O2 -Wall -Wextra -Werror -fsanitize=undefined protocol.c oracle.c -o /tmp/dnbox-core1-protocol && /tmp/dnbox-core1-protocol. Pinned JieLi pi32v2 clang -target pi32v2 -Oz -ffreestanding -fno-builtin -DDNBX_PI32=1 -ffunction-sections -fdata-sections compiles 248 bytes of standalone text (30+22+34+40+122), 40 B of four-byte aligned job slots plus one 4-byte main join sequence, no unresolved helper. Not final linked cost: scheduling, DNR3 integration, actual mix handoff, generation lifetime and quarantine/recovery absent. State must not be taken out of protected POOL; 44 B is standalone state, not evidence of placement/availability.
Protocol per job: QUEUED / STARTED / DONE tagged by shared 30-bit stretch epoch. Only its designated worker can publish STARTED before any engine write, and DONE after result + barrier. Main cannot claim while worker is runnable. On timeout, a true hardware stop-plus-write-drain acknowledgment allows fallback only if still QUEUED. If STARTED, report deadline failure and quarantine mutable owner; never rerender/reuse this half. If DONE, use exactly once; stale cookie rejects. Epoch wrap requires a quiescent reset of slot cookies, never allowed while stopped state is unknown. The host oracle models acknowledgment as input; HAL does not prove this by a volatile flag or memory barrier alone.
DNR3 rn-pulse staging holds last payload + count mod 256 + explicit valid bit (256 events still carry a last payload). Single ordered main combine in 909, 808, A, B, BREAK sequence, publish at most once under monotonically increasing join sequence and only on complete all-job admission, discard stale WATCH generation. Requires proof the consumer cannot observe partially staged pulses and no unstaged concurrent publishers. Engines' additive mix must remain ordered at their current stage joins; this fixture tests protocol and DNR3 algebra, not actual concurrent DSP/ALNK/USB.
Firmware c1_take_over currently re-runs timed-out in-flight jobs and rd.voice is a shared non-atomic RMW. fm1_cpu1_wait sets distinct bad-mailbox and timeout codes, but fm1_cpu1_halt only toggles bits and syncs, with no documented stop/drain ack. Recovering a prematurely halted owner while preserving warm state is unsolved: exact model original_bass has 24,424 B as two equal slots; a raw owner copy costs 12,212 B before any externally pointed FX history, far more than available. This is the cost of a naive full copy, not a proof of minimal journaling bytes. Lab app +4/+12 B, usable POOL +412 against hard 512. Do not route, promote, or fake an audio recovery from this model.
