# Brainwave vibrato arm, prototype rejected for adoption

The original current compiled note path reaches the first-empty-key path and clears its LFO delay accumulator and latch. At physical delay ≥.01 s it calls rate-zero then depth-zero original senders; the latter receiver has an order/rate guard. Repeated/overlapping non-empty key input keeps prior state. Brainwave raw #91=.3531042039 maps to .851302187571 s; Raw #91=0. The actual timer uses strictly greater elapsed and delay ≥.2 s for the restart fanout, so a .5 s first note does not itself reach this restart. A deliberately forced first-note restart was only a sensitivity test, never a valid firmware change. Route parameters used by the later enable event are not proven from saved AU terminal output.

Standalone boundary regression is in [lifecycle.c](../../../experiments/original_synth/sj6-vibrato-lifecycle/lifecycle.c). The pause-only actual compact host donor is opt-in, one owner/clock, pre-delay Mono only, and not shipped. Raw #91=0 and enable-switch-off output remained bit-identical. Apparent first-note terminal drift moved Main +.12263→+.10213 Hz and Sub +.06163→+.05058 Hz; installed +.01471 and −.01164. Whole first-note signed normalized error moved Main −1.093→−1.046 dBr and Sub +3.545→+3.540, so pause alone is rejected as a match fix.

Direct original and compact pitch-ratio traces at the actual pending roles/blocks differed by at most 0.162452 parts per million with the free clock, or 0.333690 parts per million with the phase frozen. The tested same-rate algorithm and depth words do not explain the terminal discrepancy. No phase/rate correction or gain fit.

Separate saved playing-core admission: original Brainwave uses Normal, Raw OTA, and compact projection already selects both. Flipping the selector moved signed error <.01 dB in measured windows.
