# Erased live sample sector at startup

The matched experiment seeds the same valid BREAK sample shadow and erased live sector, then runs normal startup with a matching owner record. Shipping 0.0.26 (`94197fc839b00aff47b98ca02f3c6396e4a6eabf`) exits on SIGSEGV before the recovered frame. The current source (`b995fb7374275e83a345fee45b7afc22d8206970`) completes restoration, draws the recovered owned splash and first UI frame, and matches the separately seeded already-live control frame.

The shipping signal replay resolves the innermost application frame to `engine_brk_loops()` at `firmware/src/app/engine.c:3154`, at the first load of `bp->slot_a`. Its caller is `ed_smp_restore_sec0()`, inlined into `ed_smp_try_restore()` and `ed_smp_recover()`. The exact shipping engine calculates `bp` from `seq.pat` before startup has bound the pattern table. This is the same missing lifecycle guard added by [the existing fix](https://github.com/gobbajogger/DnBOX/commit/11bc3f3a0e9c361dcfb51a95bbc03eef9fec7a75). Current startup binds the table and publishes the restored BREAK loops after `engine_init()`.

The original [six-pass log](shipping-startup-loop-six-pass.log) preserves shipping exit `-11`. A separate host-only [signal replay](shipping-recovery-signal.log) installs a diagnostic handler through `LD_PRELOAD` and exits `139` after recording the stack. It does not alter any renderer, startup state or firmware function. [Current replay](current-startup-loop/normal-loop.json) passes the recovery and already-live storage assertions and records the full-page frames. This is a historical shipping source failure and existing fix, with no shipping recovery framebuffer and no new firmware defect.
