# SMC Peer 138→82 row replacement: state boundary
Source: measured guarded `ui-canvas-clip-wired/tree`.
- `firmware/src/app/smc_mixer.c:1302–1306`: header commits first (may service input), then the complete peer grid paints into 138 rows without tile service, then the grid commits and services input. Knob/action/FILL UI is intentionally evaluated later and may observe newer controls.
- `firmware/src/app/ui.c:7812–7821,7866–7868,9228–9246`: strip driver fences DMA and preserves 16-row tile/hash ownership, but invokes input during transfer after strip 1 and before rendering strip 2. DMA proof is not a state proof.
- `firmware/src/app/smc_mixer.c:1083–1176`: 80-row cut intersects live fader travel (64–115) and the second button (y=74..84). Values/captions are evaluated through unlocked dry `pref_get`, `smc_led`, `smc_button_caption`, target and selection resolution, picked mask, transport metro state and theme. A strip-1 callback changing pickup, target lock or page can therefore yield a grid not equivalent to stock. Moving capture before header would also change stock semantics; moving knob resolution into it would change another producer phase.
- Required to replace the legacy painter: capture resolved frame operands (not mutable pref pointers) after header output and before grid tile emits, prove IRQ/tool callback read ownership and callback mutation with real peer fixtures, then use a single snapshot-fed painter with retained tile fences. Existing host state tests and byte-identical Clip Keys/Grid evidence do not exercise that SMC-specific adversarial window.
Not implemented without the requested existing state proof. No linked fit, frame or SRAM change.

## Bounded follow-up
- Tile order/window and RGB565 are unchanged only if every original grid pixel is preserved. A resolved snapshot alone does not preserve the required input boundary: the actual `cv_lcd_maybe_input` permits only one callback per `plat_ms()` tick, not per strip/tile. Stdout from `python3 measure.py` is a compiled counterexample using the exact current gate, demonstrating a legally different downstream read when the added raster work crosses a tick between otherwise identical tile ordinals. This is an ABI witness, not a measured native raster time or a real RGB565 trace.
- `smc_button_caption` is not a pure lookup: it can lazily invoke `smc_fx_publish` (`smc_mixer.c:1017,1027`). Resolved capture must execute that side effect once, in original lane/cell traversal order, not in each strip replay and not before the post-header point. Other constraint: each arc's raw value and each formatted number were separate original `pref_get` reads, so an unverified one-value cache can change behavior even while excluding foreground input.
- A straightforward bounded snapshot with original-sized value buffers, resolved colors/gates, pointers only for witnessed fixed button strings, and no overlay assumptions is 1,616 B on x86-64 / 1,324 B on 32-bit ABI. This is a conservative witness layout, not a lower bound; a compact cell encoding or reuse of an existing owner may reduce it, but no such liveness proof exists. No allocation is committed.
- Therefore no production/diagnostic patch was adopted and no claim of native input or pixel parity is made. Real qualification requires a same-schedule native trace (timestamps and queue order, SPI window and bytes, hashes and knob/FILL output) or a design that renders both parts before the first input-service batch without retaining a full backing store. Timer cadence, input order, or fallback must not be altered to obtain parity.
