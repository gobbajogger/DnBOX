# Synth One: fit the wet path without changing the program

## What must fit
Both stock models must run the same complete controls and live arp path, with two independently active wet synth owners. Keep flash, ordinary SRAM, buffer-pool and stack gates, no PSRAM, no device writes. Preserve the established full-bank host reference and qualify a connected candidate on Elite and Pro under the actual heavy scene: 0 late blocks and the agreed 100 µs margin (10,809 µs maximum under the 10,909 µs working target). A host null or linker pass is not a release qualification.

Latest measured guarded partial-fit donor: Elite/Pro have 1,076/1,084 B APP free; 8,756 B raw pool free, less 8,192 B reserve and an additional 512 B floor = 52 B spendable. Pool size 336 KiB; existing scratch and independent other owners are not free. The exact 44.1 kHz RevSC history is 98,760 B per owner plus separate state. E6M9 reduces this to 49,380 B/owner; across 906 cases worst signed whole output residual is −62.1 dBr. This is a useful fidelity reference, not a native memory solution. At a real Pad .2162 s setting, four original delay paths need about 229 KB of full-rate Float32 history per slot; even optimistic packed three-way full-band 4-bit storage is ~23.8 KB before metadata. Wider delays can need more. Exact source-level width already has a compact host candidate, not a free or validated connected target state.

## Recommended approaches, in parallel

1. **Recover persistent SRAM from a different subsystem, not by aliasing live owners.** Baseline bytes and maximum simultaneous liveness first. Look at the display canvas and staging or copy duplication with actual page switches and recorder/restore/BLE enabled. A buffer-per-strip display implementation only counts if every path can render the same pixels, the hardware transfer finishes before reuse, and native timing does not regress. One-day savings estimates are not fit. Do not overlap two wet histories or make a loading screen a prerequisite for playing.
2. **Use a much smaller reverb algorithm, rather than encoding the original line lengths.** Preserve independent stereo early reflection timings and decay control. Compare a 1–4 KiB short decorrelated feedback network and frequency-dependent late decay to measured original stage responses, with controls held, changing, and across preset switches. This is a hypothesis: reject it if it matches broad levels but introduces metallic ringing, loses stereo shape, or fails quiet tails. Start with reference impulse/burst and music holdouts (Pad, Organ, high-feedback, quiet-tail), then the 906-bank comparison only after a cheap candidate survives. Whole mix and independent slots both matter.
3. **Keep delay timing and feedback routing as invariants.** Check timing, all recursive taps, phase and gain at the true echo ages before choosing a codec. The recent-only treble tape and best-in-hindsight dated sparse cache missed the Pad's audible high-frequency echoes; do not repeat them. A candidate must represent *older* audible broadband data and bound repeated quantization in feedback, not just return the right average spectrum. If no independent bank fits the reclaimed budget, state the exact remaining memory or fidelity gap. Don't hide it by trimming maximum delay, missing echoes, power-cycling wet tails, or sharing owners.
4. **Protect real-time work separately.** Use slow control updates to prepare interpolation, delay addresses or scaled coefficients once when possible. Do not add burst rewrites in the audio block (the SuperJ6 tests showed the cost of that pattern). For native comparison, wait for confirmed owners and key a fixed MIDI tape to renderer frames; do not mistake an altered start frame for changed DSP. A full timing pass needs an uninstrumented strict replay as well as diagnostic attribution.

## What not to count
Moving constants to flash is useful for APP or static RAM, but tone history is continuously written. Running it in user flash, repurposing BREAK slots, storing only recent treble, or counting inactive/other-engine memory as always free does not meet the requirements. Neither exact host memory shortening nor a cheaper approximation is a finish unless one combined Elite/Pro candidate satisfies fit, sound and performance together.
