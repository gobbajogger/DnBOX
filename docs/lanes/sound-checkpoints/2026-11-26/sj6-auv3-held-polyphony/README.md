# SuperJ6 held-note polyphony, native Mac AUv3
The installed original `aumu/j6ct/AuPr` (0.999.8 build 9, exact hash in capture receipts) rendered five direct offline arms, no DAW. The Jupiter Sine test uses OSC2 alone, neutral public effects parameters, fixed velocity, mono off, and the same render partition across every arm. The held A3 is joined by 2, then 3 more keys and stays down while the additions release. Two fresh takes each of the solo and combined arms characterize repeat variation. `poly-additions` identifies contamination in the held-note projection. No original software binary or source is included.

Run `python3 score_poly.py native` with NumPy 2.0.2. Signed PCM hashes, live control readbacks, exact cue and block alignment are verified by the scorer. The two-channel jointly projected A3 changed by -0.254 and -0.166 dB at three simultaneous notes, and -0.248 and -0.146 dB at six. Maximum combined sample peaks were 0.618 and 0.632 across the two takes. This is not proof of unconditionally linear full output: signed nulls vary because oscillator phase differs across fresh takes and released notes have audible tails. Do not use the null as a per-voice gain measurement. The native result rules out the diagnostic compact route's abrupt 21.58 dB held-note jump; it does not specify the remaining absolute gain law or qualify firmware.

To reproduce the bench update, use `add_poly.py` on a scratch copy of the bench from commit 36722b9 (`main.swift`, `submit.py`). The updated profile, host queue, and submit script are also included. Compile the app locally, open the offline host, and submit `jupiter-poly` against its own job root. No saved user presets or hardware are accessed.
