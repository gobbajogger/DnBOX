# SuperJ6 factory reference batches

The factory batch is separate from the [14-program S4 guard](compare.py). It reads a SHA-256-verified build-9 IPA as data, verifies the embedded original component identity, and derives the 640-program factory plan from the audited release bank UUIDs. The release-only User Bank stays outside that scope. Keep the original installer and raw bank inputs private.

Use the exact batch plan for the real original producer and the independent DnBOX producer. Use the same 44.1 kHz, three-second stereo stimulus, authored tempo, reset, block and note schedule on both arms. The output contract is interleaved Float32 little-endian PCM in `<UID>.f32le`, its capture receipt in `<UID>.json`, and the applied control state in `<UID>.applied.json`. Both arms use the batch digest in the receipt field named `s4_inputs_sha256`; the existing scorer uses that field to authenticate the selected matrix. Readbacks must be actual applied state from the respective render engine.

```sh
python3 factory_batch.py --ipa PRIVATE_PINNED_IPA plan NEW_PRIVATE_PLAN_DIRECTORY
python3 factory_batch.py --ipa PRIVATE_PINNED_IPA score ORIGINAL_CAPTURES DNBOX_CAPTURES \
  --candidate-image EXACT_FIRMWARE --candidate-commit FULL_GIT_SHA --start 0 --count 40
python3 factory_batch.py --ipa PRIVATE_PINNED_IPA pack VERIFIED_ORIGINAL_CAPTURES NEW_ARCHIVE.zip \
  --start 0 --count 40
python3 factory_batch.py verify NEW_ARCHIVE.zip --sha256 REPORTED_ARCHIVE_SHA256
```

For scoring or packaging, `--reuse-s4 VERIFIED_RELEASE_S4_CAPTURES` admits a previously captured original S4 file only when the authenticated bank and program identities, record bytes and all stimulus fields agree. The original S4 receipt retains its own matrix hash and is validated against the unchanged 14-case plan. A partial or invalid factory capture fails without falling back. When scoring an unpacked mixed archive, supply its directory as both the original capture directory and the reuse directory. DnBOX captures remain bound to the factory plan and their own firmware source and image digests.

Packaging verifies the applied state, observed control readbacks, complete-preset marker, event schedule, PCM length, finite stereo data and PCM hash via the same checks as S4. It copies a private snapshot of the three validated members and includes a manifest with exact provenance, program and stimulus identities, source scope, per-file SHA-256 and per-file byte count. The ZIP is published locally only after all decompressed bytes pass verification. The standalone `verify` command authenticates the archive and checks its full contents without requiring an installer. It verifies archive integrity and shape; original render qualification comes from the capture checks and its source receipt.

Raw PCM is 1,058,400 bytes per program, 42,336,000 bytes per 40-program batch and 677,376,000 bytes for all 640. Measure one actual accepted batch before selecting the existing approved GitHub storage route under Rule 13. The synthetic test archive sizes do not predict the production compressed size. No original PCM has been generated by this tooling.

The [initializer checkpoint](original/engine-entry-rebuild/) currently reports the exact missing original input. The [contract test receipt](factory-batch-tests.txt) covers synthetic fixtures and leaves all 14 S4 inputs and the existing scorer unchanged.
