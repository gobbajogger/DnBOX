# Deterministic replay of a moving Synth One delay tap

Reset and replay recovered **44,100 of 44,100 actual left wet samples exactly** across the two authored factory programs. Each owner reran its original note generator, oscillator state, scheduler, pan/phaser and pre-delay filter from its genuine initial state and received its own documented restore and live event sequence. Four float input samples sufficed for interpolation in the monotone, audible segment. The independent second execution received timestamped tap queries and recorded expected answers. Those answers serve only the final byte comparison. The cursor's reconstructed value comes exclusively from newly synthesized samples.

Each six-second scene performed 144 original factory setters, one sequencer reset, seven setup/live parameter edits, 16 starts and 24 stop-all calls per owner. A 12-byte timestamped event representation would take 576 bytes for the 48 reset, edit and note calls after attachment to a known immutable factory restore. On the smaller prefix needed to reconstruct the entire audible segment, each replay dispatched four setup edits, five starts and five stops, in addition to the restore and reset. These are observed event counts in two authored scenes.

The first wet read occurred at output frame 242,550. A replay that starts when the mix first becomes audible must synthesize source frames 0–22,135 before answering it. Each owner separately exceeded one host callback period, even before adding the live firmware's other engines. The final wet query needed source frame 44,184, after which the final partial host block ran through frame 44,227. The timing uses thread CPU, excludes constructor/restore and bypasses downstream delay, reverb and master processing in the replay. Device callback timing was not measured.

The real compact pre-FX source scheduler is 9,536 bytes on this host. The raw comparison scheduler is 16,656 bytes before its dynamically owned tables and sequences. The underlying seven inline per-note DSP object groups in both actual layouts occupy **3,108 bytes on PI32v2**. This subset alone exceeds the 2,764 conditional bytes available in one stock dry INIT owner by 344. It excludes the other persistent state, live event log, interpolation cache and pre-delay effects. The raw comparison-only scheduler also has a separate 4,200-byte target layout for its 150 Soundpipe parameter ports. More compact semantic snapshots require a different state representation and independent output verification.

The long smoothed edit initially traversed the source timeline backward. Across the entire two-second sweep it made 20,096 negative moves of up to 34 frames each and reached 15,169 frames before initialization. Clamping the known pre-initialization silence to frame zero, that is a 176,333-frame backward excursion and 12,325 actual negative moves. All 22,050 audible queries in each measured scene were forward-readable with four-sample history. The pre-recorded query stream is an optimistic schedule, and preparing a future cursor before a live edit would require a predictor or continuously retained checkpoints. This experiment covers the zero-feedback left path. Changing feedback introduces dependence on earlier delayed outputs, and the right pipeline includes a second delayed tap. The full eight histories and a stock real-time implementation remain open. S6 remains FAIL.
