## Build or inspect without running audio

```sh
cd /workspace/scratch/e803955aec60/s1_dry_voice_unit
sh build.sh
sh variant_b/build.sh
build/s1_dry_host --describe
variant_b/build/s1_dry_host --describe
```

Both host builds use the same flags recorded in the pre-render declarations.
There is no native target toolchain/link, libm, timing benchmark or original
engine build. The declarations also pin binary hashes. A different compiler
may change a binary hash even when source is identical; that would require a
new explicit declaration rather than weakening the integrity check.

## Re-render into a new output directory

```sh
python replay.py --variant a --run-id review-a-first
python replay.py --variant b --run-id review-b-first
```

Each command renders the first frozen physical file: velocity 100, cutoff
2000 Hz, resonance 0.8999999761581421, depth 0; notes 36/60/84. The output
directories are new beneath `replays/`. The script refuses an existing run ID.
Expected process status is 1 because both three-note files fail the audio gate.
An error status does not mean the renderer or utility crashed: their detailed
logs and receipts identify the normal failed gate.

The complete 180 static notes can be reproduced serially with fresh run IDs:

```sh
python replay.py --variant a --run-id review-a-all --all
python replay.py --variant b --run-id review-b-all --all
```

Do not run the two render commands concurrently. Expected overall status is 1
for each complete matrix. The underlying runner's `--all` mode resumes any
already completed case by validating its stored candidate/reference hashes; the
fresh replay directories above ensure genuinely new renders.

## One direct manual comparison

```sh
variant_b/build/s1_dry_host results/review-b-mono.f32le 100 2000 0.8999999761581421 0
python ../dry_reference_packet/compare_saved.py \
  --case physical-gain/100_2000_.9 \
  --candidate results/review-b-mono.f32le \
  --output results/review-b-paired.f32
```

The renderer and comparison utility both refuse to overwrite their outputs.
The mono file is exactly 1058304 bytes; the utility constructs the paired
2116608-byte file and invokes the unchanged metric with an explicit argument
of `1` for the comparison gain. It does not estimate or apply a delay or gain.
