# Independent Synth One event review

All source-side measurements used the public original scheduler at 44.1 kHz, the checked-in original baseline controls, original tables and tuning, 2,757 silent warmup blocks, 1,378 captured blocks of 64, and fresh owners. The unchanged baseline first reproduced the stored 1,058,304-byte mono recording exactly (`b02703f0893f9e7676e4db03048f9fefe8575ae1b1a1f44da1167253309a6cd2`). Only the public wrapper's note schedule changed in the event observations. The C production tests link the actual DnBOX runtime and DSP. The firmware uses independently authored DSP; original algorithms, tables and objects are loaded only by the separate comparison executable.

A held note repeated at the same velocity produced the same original PCM as the baseline across all three pitches; lowering velocity changed the PCM. During release, a repeated note reopens the gate at its current envelope, phase and filter history. The old DnBOX code reset all of them. In the held repeat it changed 129,024 words with a peak error of 0.2141 relative to its own no-repeat branch. With the correction, matched onsets at notes 36, 60 and 84 have relative error at or below −22.3 dB for every tested same and changed velocity event. That relative time-domain measurement is diagnostic. It does not replace the program spectral/level gate. Results with original and candidate hashes appear in `review-normal.json`.

Source and DnBOX count physical Note Off events differently when two overlapping MIDI Note Ons come from the exact same source and pitch. One note-off ends that pitch in the original scheduler. DnBOX tracks the number held for each source and pitch, with one off consumed for each on. Matched balanced two-off events end the voice. No cross-engine ownership semantics were changed.

The comparison-only allocator fixture started MIDI 36, 43, 50, 58, 65 and 72, 2,560 frames apart, then MIDI 79. With all slots active the seventh note replaced slot zero even when slot three had been released just 256 frames earlier. With a fully retired hole in slot two, MIDI 79 used it and a subsequent MIDI 82 stole slot three. Retriggering an active pitch in slot two likewise makes slot three next to steal. Each check stopped all other pitches and inspected a sustained interval after releases expired. Actual original hashes and remaining peak per pitch are retained in `allocation-captures.json`.

The checked-in test now exercises real runtime note events, bit-exact repeated-note PCM at matched velocity, live velocity changes, mid-release envelope preservation, both allocation cases and the cursor advance after an active note retrigger. The independent matched run used the normal runtime note and render entry points. File `freeze-test.log` is the focused test result at source SHA-256 `90940d94f326de262bd22df5e5a3ca41f19ebc1db5c95414bb3f9f1606d8c98b` for `s1_dry_part.c`.
